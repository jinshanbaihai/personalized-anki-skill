# 制作前与制作后的双重验收

## 制作前：轻量但可追溯

先按 `exam-answer-first.md` 确认目标题型，查适用考纲、相关真题和可信人类示范解答及评分评语。批次记录阅读覆盖、示范出处及质量判断；每卡记录本卡用途及研究如何影响选材，再确定读者缺口、核心讲解与次要补充。未充分研读大量相关人类范文，不能用 AI 自写答案或只有答案键的材料通过制卡验收。已有充分同类榜样基础时允许 AI 为新题自写；验收检查其研究基础、迁移与评分匹配，不以“不是现成原答”为由拒绝。为每个主要教学支点判断例子、标准学科图、对照或其他表达能补什么；不用固定表格模板和案例配额。取舍服务学习动机。

## 作答覆盖验收

执行 `full-credit-coverage.md`：先核对整题要求及当前评分体系，再只根据可见卡面重建完整作答，逐项查分析是否真正展开、图是否支撑论证、评价是否解释条件与后果、结论是否回应题目。检查漏项和答非所问，不能按术语数量、配图数量或作者自评分验收。覆盖记录是审查索引，不是给 AI 答案盖上满分认证。

## 制作后：按真实页面读，不按作者意图打分

先反查任务与证据：本卡选材、深度与重点是否受真实答题研究指导，真题是否只是装饰性 hook，展示的考试用途与来源是否匹配；原答缺陷是否误当技巧，标作人类范文的内容是否其实由 AI 补写。缺依据先补研究。

再沿视觉顺序逐支看：对象和术语含义是否明确；条件、比较基准、每步原因在哪里；案例哪一点对应原理；图让什么关系可以直接看见；论点怎样用于目标。把实际发现的最危险缺口和修复写入 audit，不接受只有“已检查、通过”的空记录。可以用邻近新情境作制作端迁移检查；这是作者检查，不是受试者研究。

逐处检查依赖图像的文字和语音：读者能否按提示立即找到正确图、点／线／区域及比较对象；同名符号是否被误认到另一幅图；跨图映射是否解释了对应理由。记录发现的具体失配及修复位置。图存在、标签齐全或音频能播放，都不能替代这项检查。

完整同页与充分讲解同时验收。用户允许时，多个独立目标可拆；已指定的整题作答目标不能自行拆散或降档。本卡关键关系不能依赖别卡。读者曾指出的缺口要进入本批回归检查，但不要把具体案例写成所有学科永久配方。

## 工程验收

1. 生成预览，实际渲染。每页检查文字、图、MathML、语义关系、连接位置、真实语音阅读顺序。默认不隐藏必要内容。
2. 调用 `ccptAudit()`，检查溢出、重叠、正文及 SVG／表格／数学中的实际字号；目标窗口的字号是否可读仍需看截图。没有统一医学字号阈值；若在目标窗口不足自己选定的可读标准，就返工，不无限缩图。工程记录写窗口、最小正文显示字号及截图。
3. 页面只有一个播放器；所有正文节点在 reading_order 中且语音解释覆盖内容。数表以比较意义讲解，不逐格念无用数字；不能漏掉学习命题。验证暂停续播、结束重播、切卡停止和实际倍速。
4. `validate_package.py` 在隔离 Anki collection 导入两次，校验单面、身份、媒体和已评分历史不变。它不验证用户理解，也不代替真实桌面测试。
5. 原生 Anki 按 Space 不评分，Enter 只一次 Good，1只一次 Again且下一学习日；测试评分 Undo 恢复。新建测试组的 namespace/model/deck 独立，原始 notes/cards/revlog 前后比对。普通修订反而保留既有身份。
6. 交付列出“已验证”“尚未验证／待用户体验”。不能以preview成功宣称云希合成、桌面操作、手机播放或学习效果已成功。

## 原生导入容易漏掉的检查

- 同名 model 的重复导入不一定更新 CSS；读取目标 model 的实际模板和 CSS，确认目标版本已生效。共享 model 先检查影响范围。
- Anki 的 night mode 与全局 header 样式可能覆盖卡面。检查实际颜色、留白和字号，不只看独立 HTML。
- 快捷键必须从正常复习入口实测，不用手动赋值 reviewer.card 或单独调用显示方法代替；这可能绕过 scheduler 状态与计时。只撤销本次产生的测试评分。
