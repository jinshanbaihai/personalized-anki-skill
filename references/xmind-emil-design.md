# Xmind 风格与 Emil 设计：制卡端的实际工作

## 保留的用户样例特征

用户展示过 `xmind-250911-02` 的 tax incidence 导图，并明确更喜欢它，原因是能同时看到完整论证。样例由左侧核心向右展开主干，再细分解释和条件；核心较醒目，主干紧凑，末端是足够理解的短句，连接线真正表达从属与展开。示例的蓝色核心、黑色主干、白底和同色连线是可参考的实例，不是统一色表。

用户同时指出旧图里的长段可以继续细分。新卡要保留它的全局可见、层次清楚和简洁统一，同时改善长末端段落；不能只复制旧图，更不能改回没有连接关系的竖向文字列表。字号、间距和画布比例围绕一页看清完整因果设计，不设统一的大字号或固定分支数量。解释足够与整图可见都要兼顾，不能靠删掉条件和原因来凑一页。

阅读路径通常从左往右或从上往下；分类从中心分化、真实循环用环形也可能更合适。颜色帮助分组、比较或追踪同一链条；同色降低理解成本时就用同色，需要区分时再变化。English 术语突出，中文承担日常说明和完整解释。

## 一次提炼，直接复用

上面的样例特征已经完成提炼，是 skill 内置的设计依据。每次制卡直接组织成核心、主干和解释分支，再判断各节点用文字、表格还是图来解释，然后绘制连接关系；不搜索或打开用户的 Xmind 库，不要求上传样例，也不启动 Xmind 软件。不把“找样例”设为制作前置步骤。

只有用户明确要求改变现有风格，才按其新样例更新规范。若输入母件本身就是 Xmind，则读取它是为了提取本次学习内容，与反复制卡前查风格无关。Anki 输出可采用 SVG／HTML 或适合的绘图工具，用户继续只在 Anki 学习。

概念卡让导图承担定义、比较与因果。讲图卡先保证科学图准确，在图的附近组织原理与概念；坐标图、受力图作为导图节点或子分支存在，图内结构保持准确，不拆成树。完整母图可用于制作和梳理，单张卡应呈现当前目标完整而可读的局部关系。

## Emil skill 怎样实际参与

当前环境可用 `anthropic-skills:emilkowalski-skills`。每次涉及版式设计的制卡任务读取一次，整批卡复用；同一任务中已经读过就不重复读取。按技能目录提供的位置打开 SKILL.md，不把某台机器的缓存路径写死。按入口路由读取 apple-design 与 emil-design-eng；重点是 typography、craft、simplicity、feedback、accessibility 和高频操作的动效取舍，而不是强行加入每种 UI 效果。

实际落实到作品：层级主要靠分组、字重、适量字号差、位置与颜色；对齐与间距一致，减少装饰；播音按钮的播放、暂停、完成状态明确，键盘不抢焦点；切卡及时停止旧音频，连续快刷不等待过场。界面动效与科学过程动画分开判断，后者可能有教学价值。兼容 Anki WebView 与 reduced motion，不为桌面样张引入必须联网的组件依赖。

如果目标环境没有 Emil skill，先查技能目录或可用的公开原作者资源；确实无法加载时用本节的 Anki 适配摘要继续制作，明确它是替代方法而非已调用完整 skill。不要因跨产品缺少一个插件而让制卡停在不可用状态。原作者来源：[Emil Kowalski skills](https://github.com/emilkowalski/skills)。

## 设计选择与验收

导图组织知识，节点表达保持开放。先依据当前学习用途、读者理解缺口和成熟教材表达选内容，再判断怎样画；不要以现有组件反向决定教什么。文字、情境、科学图、表格、动画只是可选手段，避免固定左图右文或每卡相同数量的分支。

关系结构必须准确：分类、条件、因果、比较、分流与合并不能为了对齐而混同。图形应当增加可观察的信息；结果图不能单独解释机制，文字流程框不能自动替代科学图。图文各有作用并明确对应，当前完整思路一页可见，解释不能依赖隐藏内容。

科学图优先研究可靠教材的表达及其作用，按 syllabus 深度简化后核对；保留帮助理解的关键关系，不引入额外高阶构造。情境可以帮助建立具体理解，表格可以支持比较；采用哪种或怎样组合由内容决定。

逐卡按 SKILL.md 的“制作、验收与交付”检查理解、应用、表达与技术运行。实际截图和操作优先于风格标签，但视觉整齐和按钮可用不证明已经教会读者；发现知识跳步、图文重复、评价未展开或考试用途无依据时需回到内容设计。
