# 为理解与快刷设计复习安排

此参考仅在用户要求安排复习时使用，不把改动调度器当作每次制卡的默认步骤。

先了解实际操作：普通复习还是预览；翻面前是否尝试 recall；Enter 实际提交什么；能接受的最轻反馈；学习目标、考试日期、频率与眼睛状态；旧评分是否可信。检查当前软件、客户端兼容性、预设、父子牌组限制和实际历史。已有问卷答案直接复用，只问确实缺失的信息，不重复整套问卷，不要求持续写日志。

Enter 在显示答案后通常是 Good。只看懂反面不能等同于回忆成功；FSRS 不用停留时间纠正这个误差。用户以 Enter 继续快刷，明显没懂或忘记时用 1（Again）。保留其操作，不强迫每张都变成严格 recall 测试；但明确这种 Good 是混合信号，不能据此保证模型预测的真实 retention。不要把快刷全部映射成 Hard，Hard 本来也表示成功回忆但有困难。初次接触可以直接翻面学；以后再测这个目标。不要要求把所有解释逐字复述，也不要悄悄把 Good 改成 Next 或改写历史。

用户需要逐渐增加间隔，但默认 Good 链增长后出现得过少；不是要求固定间隔上限。普通卡当前使用 FSRS desired retention 0.95，作为比默认 0.90 更早复习的试用设置。不另加 7／14／30 天上限，不手改 FSRS 的 stability 增长权重。提高 desired retention 缩短相同 memory state 下的安排间隔，实际后续增长由 history 与 FSRS 决定，不保证每次固定乘某个倍数。代价是复习量增加；它也不能把浏览自动变成真实 recall，更不是用户个人记忆率或试卷正确率。重要卡由用户后来刷到时标记；flag 只标记重要性，不会自动改变调度，更不能拿 Easy／Hard 表达重要程度。需要不同频率时，用明确的预设或牌组设置，不写隐形改间隔的脚本。尚未确定考试日期时不编造考前冲刺安排。

旧评分掺杂浏览行为时，保留记录，暂不据此声称已拟合个人曲线。先用默认参数，再根据新规则下的真实反馈决定何时优化、是否设置优化用的历史截止日期。开启或调整时通常不立即批量重排全部到期日；说明哪些改动只影响后续复习。用户现行偏好是当日不重复：learning 与 relearning 都使用单一 `1d`，覆盖新卡与遗忘卡。连续 Again 时 leech 采用 tag-only，不自动 suspend；同时检查父子牌组、当日覆盖与 review cap 是否会隐藏次日到期卡。Again 后进入下一个 Anki 学习日；翌日 Good 退出该阶段，后续间隔由 FSRS 决定。不要用空 steps 猜测一定次日出现，也不要把固定 1d 扩大为所有 Good 固定每天出现。官方通常建议 FSRS 的 steps 小于一天，此处因用户明确节奏要求采用 1d；要说明这一取舍并实际测试 Again→次日 Good 与连续 Again。既有已经安排的 learning 卡不会仅因设置改变自动挪动；若发现今天已按 Again 且仍在当日队列的卡，只处理这些明确受影响的卡，保留正常复习历史。用户要求解除每日新卡限制时，实际检查 preset、本牌组、today 与 parent 的限制及 review cap 对 new 的影响；Anki 的有限大数应如实称为实际近似不设限。
